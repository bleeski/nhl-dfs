# B6 preregistration: a unit-level Gamma factor for the thin 3+ point tail (C25, [BEN] flag 116)

Written and committed 2026-10-16, after C25's clean calibration (docs/calibration/2026-10-16.md and .json) and its co-ceiling
cause test, before any Gamma factor code exists (C25 writes none) and before any test date below is simulated. The git
history is the proof of order. The text above the result marker is never edited; the chunk that runs the test (C13 or a
later experiment) appends its result below the marker, and any rule it changes after seeing a number is named there, with
the number that prompted it, in its tracker log line and in its report to Ben.

## The question

B6: real skaters have 3+ point nights more often than the simulator expects. In C25's clean report (league constants
recomputed without the 10 graded dates, 1,500 scenarios per date, seed 20260929) points>=3 is 66 observed against 46.7
expected (ratio 1.41, FLAG), while points>=2 is 246 against 235.8 (1.04) and goals>=3 is 8 against 4.2 (too few to flag).
The body of the points distribution is right and the far tail is thin. B6 proposes a unit-level Gamma factor: on a given
night one line or power-play unit runs hot together. This file fixes, before any of it is built, how that factor is set
and how it is judged.

## What C25's co-ceiling result predicts for this factor

The co-ceiling cause test (flag 115) named "within-line correlation too strong": forwards the simulator puts on one line
who really were linemates had joint 2+ point nights at 0.60 of the simulated rate after the marginal adjustment (90%
interval 0.47 to 0.75; 36 observed against 47.8 expected). A unit-level Gamma factor raises within-unit correlation by
construction, so it pushes that group further from 1. It is therefore expected to fail the co-ceiling guard below, even
if it fixes the points>=3 ratio. This is a prediction written before the test, not a result.

The same test also showed the simulator's lines missing real linemates: actual linemates it split up ran at 2.91 (2.18 to
3.71; 26 observed against 9.4 expected) and pairs it put together that were not linemates at 0.28 (0.16 to 0.41; 8
against 32.0). That cause was not named, only because of a floor of 10 expected joint events that C25 added to Ben's
default rule (9.4 is under it); Ben's default without the added floor would have named both causes ([BEN] flag 118).
Better line identity is a different change from this factor and is not preregistered here.

B6's other candidate, lightening C5's 300-minute prior for high-exposure players so stars keep more of their own scoring
rate, raises individual tails without touching within-line correlation. It is a separate challenger and is not
preregistered here.

## The factor (built later, in C13 or an experiment; not in C25)

Per scenario, per team, per forward line and per PP unit (the simulator's units in `sim/game.py`, `m_f` and `m_pp`), draw
G ~ Gamma(shape 1/v, scale v): mean 1, variance v, from its own seed stream, so v = 0 reproduces today's draws exactly. In
`_allocate`, the scoring weights of that unit's members are multiplied by its G for the goals of that strength (even
strength: the scorer's forward line; power play: the PP unit). Team goal counts come from the game process and do not
change, so the factor only moves goals between units within a scenario.

Required property, added after run C2's co-ceiling numbers and before any tail-test number: on the design dates, each
skater's simulated expected goals and expected assists per dressed game with the factor on stay within 2% of the
factor-off values (the assist pilot runs after the factor, or the factor is renormalized). A build that misses this is
rejected before the test dates run, so a factor cannot pass by raising everyone's scoring.

## Dates

Design dates (the 10 graded dates of docs/calibration/2026-10-16, `pick_dates(1, 10)`, 79 games): 2025-11-07, 2025-11-22,
2025-12-08, 2025-12-23, 2026-01-10, 2026-01-26, 2026-03-01, 2026-03-16, 2026-03-31, 2026-04-16.

Test dates, by flag 116's rule (computed 2026-10-16 from the history store, none simulated): of the 137 regular-season game
days of 2025-26 left after pick_dates' 30-day skip, remove the design dates and every game day within 3 calendar days of
one (76 remain), then take 10 evenly spaced (numpy `linspace(0, 75, 10)`, rounded): 2025-11-11, 2025-11-26, 2025-12-13,
2025-12-28, 2026-01-05, 2026-01-21, 2026-02-05, 2026-03-11, 2026-03-27, 2026-04-12 (70 games: 9, 15, 13, 5, 5, 6, 7, 2, 2
and 6).

## Constants

`validate.clean_constants(design + test dates)`: the league constants recomputed without both sets (flag 114's method),
passed through `report(cfg, model_cfg)`. The shipped config files are not changed.

## Setting the variance (design dates only)

Grid v in {0.05, 0.10, 0.20, 0.35, 0.50}, each run on the design dates with seed 20260929 and 1,500 scenarios per date.
Among grid values whose design points>=2 ratio stays within 0.05 of the factor-off value, choose the one whose design
points>=3 ratio is closest to 1.0 (ties: the smaller variance). If none qualifies, the factor is rejected and the test
dates are not run.

## The test (one run on the test dates, seed 20260929, 1,500 scenarios per date)

Run the test dates twice, factor off and factor on at the chosen v, with the constants above. The factor passes only if all
of these hold:

1. points>=3 ratio with the factor inside 0.8 to 1.25 (B6's bar).
2. points>=2 ratio with the factor within 0.05 of the same test dates without it. This changes Ben's default, which
   compared with the design-date report's value; same dates on both sides compares like with like.
3. No rate or PIT row that is ok without the factor becomes FLAG with it (added to Ben's default).
4. No co-ceiling group's adjusted ratio (flag 115) with the factor sits further from 1 than its distance without the factor
   plus its 90% half-width without the factor (added to Ben's default; see the prediction above).

If the test dates without the factor already show points>=3 inside 0.8 to 1.25, the deficiency did not replicate on new
dates: the factor is not shipped, and that is the result (added to Ben's default).

## Power, and what one season can and cannot say

Assuming about 47 expected 3+ point nights, as on the design dates, the chance that observed over expected lands inside
0.8 to 1.25 is 0.870 if the true ratio is 1.0, 0.614 at 1.2 and 0.185 at 1.4 (Poisson counts 38 to 58). The test dates have
70 games against 79, so expect about 41.6; then the same chances are 0.849, 0.640 and 0.226 (counts 34 to 52). So a factor
that truly fixes the tail fails bar 1 about one time in seven, and a factor that does nothing passes it about one time in
five; the "did not replicate" exit fires on about one test in five even when the true ratio is still 1.4. One season, 10
dates and about 40 to 70 events are a screen, not a verdict of record.

## What a result decides

Pass: whether and how the factor ships is decided by C13's gate reading this result; this file sets no shipping rule.
Fail or not replicated: the challenger is rejected (a valid DONE outcome for an experiment chunk), and the next challenger
needs its own preregistration.
